# Security Policy

## Supported Versions

| Version | Supported |
|---|---|
| 1.0.x | Yes |

Only the latest minor release receives security updates. Users are encouraged to upgrade to the most recent version.

## Reporting a Vulnerability

If you discover a security vulnerability in @vetwo/docs, please report it responsibly. Do not open a public GitHub issue for security vulnerabilities.

### How to Report

1. **Email**: Send a report to the maintainers via [GitHub Security Advisories](https://github.com/vetwo/docs/security/advisories/new).
2. **Include**: A description of the vulnerability, steps to reproduce, the potential impact, and any suggested fixes if applicable.
3. **Response time**: Expect an initial acknowledgment within 72 hours.

### What to Expect

- We will confirm receipt of your report and provide an estimated timeline for a fix.
- We will work with you to understand and validate the issue.
- A fix will be developed, tested, and released as a patch version.
- You will be credited in the release notes unless you prefer to remain anonymous.

## Scope

This security policy applies to the `@vetwo/docs` npm package and the source code in this repository. It does not apply to:

- Third-party plugins or themes not maintained by the @vetwo team
- Documentation content generated by users
- Dependencies (report upstream vulnerabilities to the respective maintainers)

## Best Practices

When using @vetwo/docs in production:

- Keep the package updated to the latest version.
- Review generated output before deploying to public-facing servers.
- Use a Content Security Policy (CSP) when serving generated documentation.
- Validate any user-supplied frontmatter or configuration inputs.
